## 1. Executive Summary

SafeVoice is a secure digital platform designed to help victims of Gender-Based Violence (GBV) and child abuse report incidents safely. Functioning as a comprehensive Case Management System, it connects victims to immediate help while providing social workers and decision-makers with the tools needed to track cases from the first report to resolution. It addresses critical gaps in existing platforms (like SWIMS and the Boame App) by prioritizing anonymity, offline accessibility, and unified integration between police and social welfare.

## 2. Core Workflows (The Happy Path)

- **Victim Reporting (Anonymous)**: Victim visits the mobile-friendly portal, submits a report (with optional voice notes/photo evidence), and can optionally create an anonymous secure chat account.
- **Quick Escape**: Victim clicks the floating "Quick Escape" button; the application instantly replaces the current tab's history and redirects to Google.com to hide activity from abusers.
- **Caseworker Triage & Chat**: Social worker logs into the dashboard, views assigned pending cases, categorizes them, and communicates with the victim via secure, encrypted in-app chat.
- **Analytics & Decision Making**: Super Admins view real-time heatmaps (via Mapbox) and demographic charts to identify high-risk regions and trends.

## 3. Architecture & Tech Stack

- **Frontend**: Next.js (App Router), TailwindCSS, React (Offline-first PWA approach).
- **Backend**: Next.js Server Actions.
- **Database & Auth**: Supabase (Postgres for relational data, Supabase Auth for RBAC).
- **Storage**: Supabase Storage for evidence uploads (photos/audio).
- **Security & Encryption**: Custom text/file encryption (utilizing `NEXT_PUBLIC_ENCRYPTION_KEY`), Supabase Row Level Security (RLS).
- **Analytics Mapping**: Mapbox GL (for heatmaps).
- **Deployment**: Vercel.

## 4. Edge Cases & Error Handling

| Scenario | Expected System Behavior |
|----------|--------------------------|
| **Abuser unexpectedly enters the room** | "Quick Escape" button immediately navigates away and optionally clears local storage. |
| **No Internet Connection in Rural Area** | App gracefully handles offline state (PWA) or falls back to SMS/USSD reporting (requires gateway integration). |
| **Case is closed or abandoned for X days** | "Data Expiry" job automatically encrypts or permanently deletes sensitive evidence and PII from live storage. |
| **Database connection fails during report** | System stores the report locally in IndexedDB and syncs when connection is restored. |

## 5. Non-Functional Requirements

- **Performance**: Mobile-first, extremely fast time-to-interactive (TTI) for users on 3G networks.
- **Security**: 100% Anonymity option. Data encryption at rest for all stories and evidence. Strict Role-Based Access Control (Super Admin vs. Social Worker).
- **Safety**: UI must not look overly "medical" or "official" on the victim portal to avoid suspicion if briefly glanced at by an abuser.

## 6. Finalized Decisions (Post-Review)
- **SMS/USSD Integration**: Deferred for MVP. Will be simulated in the UI for now.
- **Data Expiry Timeline**: 30 days post-closure. Evidence and identifying details will be automatically encrypted/deleted after 30 days.
- **Data Scrambling Method**: Hybrid approach. Application-level AES-256 encryption for highly sensitive text (stories/names) before sending to Supabase, combined with Supabase RLS for robust access control.
- **Design Aesthetics**: Discreet but standard portal. Soft, calming UI (e.g., modern, clean, non-urgent colors) that doesn't immediately look like a crisis center, maintaining safety for the victim.
